# PyLLM — Design Spec

**Date:** 2026-06-22
**Status:** Approved (design), pending implementation plan
**Series:** Project #11 in the "from scratch in Python" educational collection
**Role in PyStack:** The **brain** — the part of the school that reads, learns, and dreams up new text.

## 1. Summary

PyLLM is an educational large language model built from scratch in Python. It
teaches how modern AI language models work by building one, rung by rung, from a
trivial bigram model up to a full GPT-style Transformer. Every concept is
explained with analogies a 12-year-old can follow, every layer is built and
tested in isolation, and the whole thing is developed with TDD.

The default demo: a model that **dreams up new Pokémon** (names and
descriptions). It ships with a small pre-trained checkpoint so it generates text
the instant you launch it, and you can also train your own model on any text file.

## 2. The mantra, applied

- **Pure from scratch, on top of numpy only.** numpy is permitted for fast array
  math (the one dependency). *Everything that makes it a language model is ours:*
  the autograd engine, neural-net layers, attention, the Transformer, the
  tokenizer, the optimizer, the training loop, and sampling.
- **Python 3.14**, managed with `uv`.
- **TDD** throughout; **ruff** + **pyright** clean.
- **Docs-first** with kid-friendly analogies in `docs/concepts/`.
- **Zero dependencies beyond numpy** (plus the standard dev/test/docs tooling
  used across the series).
- **No `TYPE_CHECKING`, no `from __future__ import annotations`.**

## 3. The teaching ladder

Each rung is a real, trainable language model. Each one fixes a concrete
weakness of the rung below it, so the learner feels *why* each idea exists.

1. **Bigram** — "what character usually comes next?" A lookup table of
   probabilities. Teaches: vocabulary, probability distributions, sampling, loss
   (cross-entropy).
2. **MLP** — a small neural network over the last few characters. Teaches:
   embeddings, hidden layers, learning weights with gradient descent.
3. **Single self-attention head** — tokens "look back" at earlier tokens to
   decide what comes next. Teaches: the core attention mechanism (query/key/value).
4. **Multi-head attention** — several attention heads looking for different
   patterns at once, combined.
5. **Full GPT** — stacked Transformer blocks (multi-head attention +
   feed-forward + LayerNorm + residual connections) with positional information.
   The real thing.

## 4. Architecture

Each module has one clear purpose and is testable in isolation.

```
src/pyllm/
  autograd/      Tensor wrapping a numpy array + reverse-mode autodiff.
                 Records every operation so .backward() can flow gradients
                 through the whole network automatically (mini-PyTorch).
                 THE ENGINE — every model on the ladder reuses it.
  nn/            Neural-net building blocks built ON TOP of autograd:
                 Linear, Embedding, LayerNorm, Dropout, softmax,
                 cross-entropy, gelu, self-attention head, multi-head
                 attention, TransformerBlock, and a Module base class for
                 parameter collection.
  tokenizer/     char-level tokenizer + a from-scratch BPE tokenizer
                 (learns merge rules from text).
  models/        bigram, mlp, gpt — assembled from nn building blocks.
  training/      optimizer from scratch (SGD + Adam), batching/data loading,
                 and the training loop.
  data/          corpus loader + bundled pokemon_corpus.txt.
  generate.py    sampling strategies: greedy, temperature, top-k.
  checkpoint.py  save/load model weights (numpy .npz) + config metadata.
  cli.py         the REPL + `train` + `tokenize` commands.
  _version.py    (generated by hatch-vcs)
tests/           mirrors src/, one focused test module per unit.
docs/concepts/   kid-friendly explanations.
```

### Key design decisions

- **Autograd from scratch.** A `Tensor` class wraps a numpy array and remembers
  the operations performed on it (a computation graph). Calling `.backward()`
  walks the graph in reverse and accumulates gradients — exactly how real
  frameworks work. We build the engine once (add, mul, matmul, sum, softmax,
  etc.), then *every* layer and model is built on it. This is the single most
  illuminating piece of the project.
- **numpy is the math backend only.** It is used inside `Tensor` ops for fast
  array arithmetic. It is never used to compute gradients for us — that is the
  whole point of the autograd engine.
- **Module base class** collects parameters so the optimizer and checkpointer can
  find every weight generically.

## 5. Data flow

**Training:**
```
text file → tokenizer → integer ids → batches (x, y)
  → model forward (autograd Tensors) → loss (cross-entropy)
  → loss.backward() → optimizer.step() → repeat
```

**Generation:**
```
prompt text → tokenizer → ids → model forward → probability over next token
  → sample (greedy / temperature / top-k) → append → repeat → decode → text
```

## 6. User experience (CLI)

- `uv run pyllm` — **chat/generate REPL.** Loads the bundled pre-trained Pokémon
  checkpoint and dreams up new Pokémon immediately (no training wait). Exposes
  temperature and top-k knobs.
- `uv run pyllm train` — train your own model: choose a rung on the ladder, point
  it at any text file (defaults to the bundled Pokémon corpus), watch the loss
  drop, and save a checkpoint.
- `uv run pyllm tokenize` — show how a piece of text is split into tokens (a
  hands-on teaching demo).

The bundled Pokémon corpus is small enough to train a tiny GPT on a laptop CPU
in minutes.

## 7. Correctness & testing (TDD)

- **Numerical gradient-checking for the autograd engine.** Compare each op's
  analytic gradient against a finite-difference approximation. This proves
  backprop is correct before anything is built on top of it.
- **Each layer tested in isolation** (shapes, forward values on known inputs,
  gradient flow).
- **Overfit-a-tiny-batch end-to-end test.** A model that cannot drive the loss
  toward zero on ~10 memorized examples is broken; this is a fast, decisive
  smoke test of the entire stack (tokenizer → model → loss → optimizer).
- **Deterministic seeds** so tests are reproducible.

## 8. PyStack integration (done immediately)

- Add a new Pebble module **`import "llm"`** exposing functions such as
  `llm_generate(prompt)` (and helpers to load a checkpoint / set sampling
  options) so any Pebble program can generate text using PyLLM.
- Add PyLLM as the **11th project ("the brain")** to the PyStack README table
  and integration layer.

## 9. Documentation

`docs/concepts/` kid-friendly write-ups, including:
- *What is a token?* (chopping words into Lego bricks)
- *What is an embedding?* (giving each token a location on a map of meaning)
- *The breadcrumb trail* (how autograd remembers operations to learn from mistakes)
- *Attention is re-reading a sentence* (how a token decides which earlier words matter)
- *How a Transformer is built* (stacking the pieces)
- *How a model learns* (loss, gradients, the training loop)

Plus the standard README with features, an example session, and the "Related
Projects" series table.

## 10. Out of scope (YAGNI)

- GPUs / CUDA, distributed training, mixed precision.
- Pretraining on large internet corpora.
- Instruction tuning / RLHF / chat alignment (it generates, it does not "follow
  instructions").
- Alternative architectures (RNNs/LSTMs, state-space models).
- A web UI (the REPL is the interface; PyStack/Pebble is the programmatic interface).

## 11. Open questions

- Exact contents/size of the bundled Pokémon corpus (hand-assembled during
